Étape 1

Analyse et Configuration Exacte

Le secret d'un portage réussi réside dans les fondations.

Ce que la vidéo nous apprend

En analysant les frames du Niveau 1 (les rues de Gotham), on remarque que les contrôles ne sont pas ceux d'un jeu de plateforme flottant comme Mario, mais rigides et punitifs comme Contra ou Castlevania.

  • Saut à hauteur variable : Plus on maintient le bouton appuyé, plus Batman monte haut. Si on relâche, la vélocité verticale est coupée drastiquement.
  • Double Saut : Indispensable. Le deuxième saut déclenche une animation de salto (flip) et réinitialise la vélocité verticale.
  • Attaque contextuelle : Le bouton "Attaque" lance un Batarang si l'ennemi est loin, mais déclenche un combo de mêlée (cape/poing) si une Hitbox ennemie est proche.

Étape 2

L'Arbre de Nœuds Professionnel

Ne mettez pas toute la logique dans un seul script.

Dans les tutoriels pour débutants, Batman a un Sprite2D, un CollisionShape2D, et un script géant de 400 lignes. C'est un cauchemar à maintenir. Sur Godot 4, nous utilisons une approche orientée Composants.

Pourquoi cette structure ?

CollisionShape2D (racine) : Ne sert QUE pour empêcher Batman de passer à travers le sol ou les murs. Il doit être petit, souvent juste un rectangle autour des pieds/jambes.

HurtboxComponent

C'est la zone vulnérable de Batman. Si le poing d'un clown touche cette zone, Batman perd de la vie. L'isoler dans un Area2D séparé permet de désactiver les collisions temporairement (frames d'invincibilité après un coup) sans que Batman ne passe à travers le sol !

StateMachine

Au lieu de faire des if is_attacking: ... elif is_jumping: ... infiniment complexes, chaque "état" (Courir, Sauter) a son propre script simple et propre.

Étape 3

Le Secret des Combats : Hitbox & Hurtbox

La méthode des studios professionnels pour gérer les collisions.

Sur la Megadrive, les combats de mêlée sont extrêmement précis. Pour recréer cela, nous ne vérifions pas si le corps entier de Batman touche le corps d'un clown. Nous vérifions si la Hitbox (le poing, la cape) de l'attaquant intersecte la Hurtbox (le corps) du défenseur.

Implémentation (Script HitboxComponent)

# hitbox_component.gd (À attacher au noeud MeleeHitbox de type Area2D)
class_name HitboxComponent
extends Area2D

@export var damage: int = 1

func _init():
    # S'assurer que la hitbox écoute les collisions avec les hurtboxes
    collision_layer = 0
    collision_mask = 2 # Couche 2 = Les Hurtboxes ennemies

# Astuce Pro : L'AnimationPlayer va activer/désactiver la propriété 'disabled'

Étape 4

Le Cerveau : La State Machine

Gérer les actions complexes sans s'arracher les cheveux.

Au lieu de mettre toute la logique de déplacement dans _physics_process du Player, nous la dédions à des scripts d'état. Voici comment structurer l'état de "Saut" (JumpState), qui gère la hauteur variable et le double saut (le fameux flip de Batman). 

# jump_state.gd
extends State # Hérite d'une classe de base virtuelle

@export var player: CharacterBody2D
@export var animation_player: AnimationPlayer

var jumps_made: int = 0
const JUMP_VELOCITY = -400.0
const DOUBLE_JUMP_VELOCITY = -350.0

func enter():
    # Appelé quand on entre dans l'état Saut
    player.velocity.y = JUMP_VELOCITY
    animation_player.play("jump_rise")
    jumps_made = 1

func physics_update(delta: float):
    # 1. Gérer le relâchement du bouton (Variable Jump Height)
    if Input.is_action_just_released("jump") and player.velocity.y < 0:
        # Coupe l'élan pour retomber plus vite
        player.velocity.y *= 0.4 

    # 2. Gérer le Double Saut
    if Input.is_action_just_pressed("jump") and jumps_made < 2:
        player.velocity.y = DOUBLE_JUMP_VELOCITY
        animation_player.play("double_jump_flip")
        jumps_made += 1

    # 3. Transitions
    if player.velocity.y > 0 and jumps_made == 1:
        animation_player.play("fall")
        
    if player.is_on_floor():
        Transitioned.emit(self, "Idle") # Retour au sol

Détail Crucial : Le saut variable

La ligne player.velocity.y *= 0.4 lors du is_action_just_released est ce qui donne le feeling arcade parfait. Si le joueur tapote brièvement le bouton, Batman fait un petit saut pour esquiver un tir bas. S'il maintient le bouton, la vélocité n'est pas coupée, permettant de franchir de grands obstacles.

Étape 5

Le Cœur Physique (Player.gd)

Godot 4 simplifie énormément la boucle physique principale.

Dans notre architecture, le script attaché au nœud CharacterBody2D principal est extrêmement léger. Son rôle principal est d'appliquer la gravité (qui est constante) et d'appeler la fonction de déplacement de Godot 4 : move_and_slide(). 

# player.gd (Attaché à la racine CharacterBody2D)
extends CharacterBody2D

# Récupère la gravité depuis les paramètres globaux du projet
var gravity = ProjectSettings.get_setting("physics/2d/default_gravity")
var gravity_multiplier = 1.5 # Pour un feeling Megadrive (chute plus lourde)

@onready var sprite: Sprite2D = $Sprite2D
@onready var state_machine = $StateMachine

func _ready():
    # Initialise la State Machine en lui passant la référence du joueur
    state_machine.init(self)

func _physics_process(delta: float):
    # 1. Application de la gravité indépendante de l'état
    if not is_on_floor():
        # Astuce: Ajouter une limite (Terminal Velocity) empêche 
        # de passer à travers le sol lors de longues chutes
        velocity.y = minf(velocity.y + (gravity * gravity_multiplier * delta), 800.0)

    # 2. La State Machine gère les inputs et modifie velocity.x et velocity.y
    state_machine.physics_update(delta)

    # 3. Gérer l'orientation visuelle (Flip du sprite)
    if velocity.x > 0:
        sprite.flip_h = false
        # Ne pas oublier de retourner la Hitbox Melee si elle est asymétrique !
        $MeleeHitbox.scale.x = 1
    elif velocity.x < 0:
        sprite.flip_h = true
        $MeleeHitbox.scale.x = -1

    # 4. Magie Godot 4 (sans arguments, utilise la variable globale 'velocity')
    move_and_slide()
