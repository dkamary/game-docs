Chapitre 1

Plateformes Mobiles & One-Way

Le secret d'un Level Design dynamique sans bugs physiques.

AnimatableBody2D

Dans les anciennes versions de Godot, faire bouger une plateforme (KinematicBody2D) posait souvent des problèmes de friction avec le joueur. Godot 4 introduit le AnimatableBody2D, spécialement conçu pour les ascenseurs et les plateformes mouvantes. Le moteur physique gère automatiquement le fait de "porter" le joueur (CharacterBody2D) qui se trouve dessus.

Simulation AnimatableBody2D

La Recette Parfaite : Path2D + AnimationPlayer

Plutôt que de coder les allers-retours dans un script, la méthode professionnelle utilise des courbes visuelles.

Arbre de la Plateforme

  • Path2D (Tracez la route ici)
  • PathFollow2D
  • AnimatableBody2D
  • Sprite2D
  • CollisionShape2D

Comment l'animer ?

Ajoutez un AnimationPlayer. Dans l'animation, créez une piste (Track) ciblant la propriété progress_ratio du PathFollow2D.

Keyframe 1: Valeur 0.0
Keyframe 2: Valeur 1.0
Réglez l'animation sur Ping-Pong (Aller-retour). Zéro ligne de code !

Plateformes Traversables (One-Way) : Pour pouvoir sauter par en dessous et atterrir dessus, sélectionnez le CollisionShape2D de la plateforme, et dans l'inspecteur, activez simplement One Way Collision = On.
Chapitre 2

Changement de Genre : Shoot 'em Up

Quand Batman s'envole en Jetpack.

Le niveau aérien transforme totalement le jeu. Batman ne subit plus la gravité classique et peut se déplacer librement sur les axes X et Y (Haut, Bas, Gauche, Droite). Nous devons adapter la State Machine (Tome 1) en ajoutant un FlyingState.

Le Script du FlyingState.gd

# flying_state.gd
extends State

@export var player: CharacterBody2D
const FLY_SPEED = 200.0

func enter():
    # Active l'animation du Jetpack
    player.get_node("AnimationPlayer").play("jetpack_idle")
    
func physics_update(delta: float):
    # 1. On annule la gravité !
    # Le script principal applique la gravité. Nous l'écrasons ici.
    
    # 2. Déplacement multidirectionnel (Input.get_vector)
    # Normalise automatiquement le mouvement en diagonale (évite d'aller plus vite)
    var input_dir = Input.get_vector(
        "ui_left", "ui_right", 
        "ui_up", "ui_down"
    )
    
    # Application directe de la vélocité 2D
    player.velocity = input_dir * FLY_SPEED
    
    # 3. Limiter le joueur aux bords de l'écran (Clamp)
    var cam = get_viewport().get_camera_2d()
    if cam:
        var screen_size = get_viewport_rect().size
        var cam_pos = cam.global_position
        
        var min_x = cam_pos.x - (screen_size.x / 2)
        var max_x = cam_pos.x + (screen_size.x / 2)
        var min_y = cam_pos.y - (screen_size.y / 2)
        var max_y = cam_pos.y + (screen_size.y / 2)
        
        player.global_position.x = clamp(player.global_position.x, min_x, max_x)
        player.global_position.y = clamp(player.global_position.y, min_y, max_y)
Chapitre 3

Le Chaos Visuel : GPUParticles2D

Pousser des milliers de particules via la carte graphique.

Le jeu original était reconnu pour repousser les limites de la puce Motorola 68000 de la Megadrive avec ses explosions remplies d'étincelles. Sur Godot 4, nous utilisons GPUParticles2D pour exécuter ces calculs sur la carte graphique, nous permettant d'afficher des dizaines de milliers d'étincelles sans aucun lag.

Simulation Étincelles

Configuration du ProcessMaterial

Dans l'inspecteur du nœud GPUParticles2D, créez un nouveau ParticleProcessMaterial. C'est ici que réside toute la magie physique des particules :

  • Direction & Spread : Mettez Spread à 180° pour une explosion circulaire.
  • Initial Velocity : Mettez une valeur élevée (ex: 300) avec une Velocity Random de 0.8 pour que les étincelles soient propulsées à des vitesses différentes.
  • Gravity : Mettez Y à 980. Les étincelles exploseront puis retomberont naturellement.
  • Color Ramp (Dégradé) : Créez un GradientTexture1D. Commencez par du Blanc, passez au Jaune, puis au Rouge, et terminez par du Noir avec un Alpha à 0 (pour qu'elles disparaissent en douceur).
Chapitre 4

Déploiement : De l'Éditeur au Joueur

Compiler le chef-d'œuvre et soigner la présentation.

Le jeu est terminé. Il faut maintenant en faire un exécutable (.exe) ou une version Web (HTML5) pour le partager.

Le Splash Screen

Ne laissez pas le logo Godot par défaut grisâtre au lancement ! Allez dans Projet > Paramètres du projet > Application > Écran de démarrage.

  • Image : Sélectionnez votre propre logo de studio.
  • Background Color : Noir complet (#000000).
  • Utiliser un filtre : Off (pour le Pixel Art).

Exportation

Allez dans Projet > Exporter. Vous devrez d'abord télécharger les Export Templates (Modèles d'exportation) de Godot (via le bouton en haut du menu).

  • Ajoutez un profil Windows Desktop.
  • Dans Icon, mettez votre fichier .ico (obligatoire sous Windows pour avoir l'icône sur le bureau).
